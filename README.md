# Predicting-Electric-Vehicle-Purchases
# EV Purchase Prediction

Predicts the probability that a person will buy an electric vehicle (`Will_Buy_EV`), based on demographic, commute, and EV-readiness features (income, charging access, subsidy availability, environmental concern, etc.).

## Problem

Binary classification task — given ~15 features about a person, predict the probability (0–1) that they will buy an EV. Evaluated using **ROC AUC**.

## Approach

1. **Data cleaning** — checked for missing values and duplicates (none found).
2. **Encoding** — categorical features (`Gender`, `City_Type`, `Current_Car_Type`, `Home_Charging_Possible`, `Subsidy_Available`, `Range_Anxiety_Level`) were one-hot encoded. Train and test sets were combined before encoding to guarantee identical columns on both sides.
3. **Baseline model** — Logistic Regression, scaled with `StandardScaler`, achieved **AUC ≈ 0.938** as a sanity-check baseline.
4. **Final model** — LightGBM (gradient boosted trees), which outperforms linear models on this tabular data by capturing non-linear interactions between features. Achieved **AUC ≈ 0.942** with 5-fold cross-validation.
5. **Feature importance** — analysis showed `Environmental_Concern_Level` and `Subsidy_Available` are by far the strongest predictors, with income, commute distance, and charging access contributing secondary signal.

## Hyperparameter tuning (Optuna)

The final model's hyperparameters were tuned offline using [Optuna](https://optuna.org/), a Bayesian hyperparameter optimization library. This tuning script isn't included in the repo, but is documented here for transparency:

- **Method:** `optuna.create_study(direction="maximize")`, optimizing 5-fold cross-validated ROC AUC as the objective.
- **Pruning:** used Optuna's `MedianPruner` to stop clearly underperforming trials early (after evaluating partial folds), which sped up the search considerably.
- **Trials:** 50 trials.
- **Search space:**

  | Parameter | Range |
  |---|---|
  | `n_estimators` | 200 – 1000 |
  | `learning_rate` | 0.01 – 0.2 (log scale) |
  | `max_depth` | 3 – 10 |
  | `num_leaves` | 15 – 150 |
  | `min_child_samples` | 5 – 100 |
  | `subsample` | 0.6 – 1.0 |
  | `colsample_bytree` | 0.6 – 1.0 |
  | `reg_alpha` | 1e-8 – 10.0 (log scale) |
  | `reg_lambda` | 1e-8 – 10.0 (log scale) |

- **Best result:** AUC 0.94222, with:
  ```python
  {
      'n_estimators': 964,
      'learning_rate': 0.12454531691539797,
      'max_depth': 3,
  ```

These best parameters are hardcoded directly into the final notebook so it can be re-run without needing to repeat the (slower) tuning search.

## Other techniques tried (didn't improve results)

To be transparent about what was explored: the following did **not** beat the tuned LightGBM baseline, so they were left out of the final pipeline:

- **Manual feature engineering** — binning age/commute/environmental concern, total charging stations, cars-per-age ratios. Tree models already captured these interactions on their own; engineered features gave no measurable lift.
- **Model stacking** — blending LightGBM, XGBoost, and CatBoost with a Logistic Regression meta-model. Result (AUC 0.9422) was statistically indistinguishable from LightGBM alone, since all three models learn similar patterns from the same features.
- **Target encoding** — replacing categorical columns with out-of-fold mean target rates instead of one-hot encoding. Result (AUC 0.9420) was essentially tied with one-hot encoding.
